# Submission deliverables

Copies of the files the hackathon asks for, in one place. The code repository and its README are at the repository
root (`../README.md`). The demo video and pitch deck are submitted through the form.

| File | Deliverable | Source of truth (regenerate there, then copy) |
|---|---|---|
| `architecture_diagram.png` | Architecture diagram, final version | `docs/architecture/full.png` (Mermaid source `docs/architecture/full.mmd`) |
| `data_contract.yaml` | Data contract for the golden C360 (`gold.c360_customer`): owner, schema, quality rules, allowed uses, refresh | `contracts/c360_customer.yaml` (also drives the publish gate, so it stays there) |
| `data_quality_report.md` | Data quality report: the issues found, records affected, how each was handled | `reports/data_quality_report.md` (regenerated by `python -m trustissues.factory.quality.dq_report`) |
| `benchmark_answers.csv` | Answers to all 50 benchmark questions (35 released, 15 released at 19:00 on 4 Oct) | `submission/benchmark_answers.csv` (written by `scripts/run_benchmark.py`, never edited by hand) |

These are snapshots. If a source file is regenerated, copy it again:

```bash
cp docs/architecture/full.png        deliverables/architecture_diagram.png
cp contracts/c360_customer.yaml      deliverables/data_contract.yaml
cp reports/data_quality_report.md    deliverables/data_quality_report.md
cp submission/benchmark_answers.csv  deliverables/benchmark_answers.csv
```
